# cheating_detection_v2

Exam cheating detection from a classroom camera, **normal / abnormal only** (no behaviour type).
Every examinee is tracked (YOLO + ByteTrack) and a 3.2 s crop of each person is classified once per second
by an X3D-L video network:

| id | class | from CVAT labels |
|---|---|---|
| 0 | normal | normal time + hard negatives (use calculator, raise hand, arrange papers, ...) |
| 1 | abnormal | suspicious_looking, communicating, exchange_object, using_phone/cheat_sheet |

`cheat_score = P(abnormal)` raises the alert.
This project is self-contained: its own code (`cheating_v2`), config, data, weights and results.

## Layout

```
cheating_detection_v2/
├── configs/default.yaml          every setting: paths, classes, clip cutting, model, training, app
├── src/cheating_v2/
│   ├── __main__.py               python -m cheating_v2 <command>
│   ├── config.py                 YAML loading, --set overrides, path resolution
│   ├── data/cvat.py              CVAT 1.1 track reader
│   ├── data/prepare.py           extract videos, cut per-person clips, write train/val lists
│   ├── data/dataset.py           clip dataset, balanced sampler, GPU augmentation
│   ├── models/x3d.py             X3D build / save / load
│   ├── train.py                  fine-tuning (bf16, EMA, mixup, cosine LR, multi-view test)
│   ├── evaluate.py               clip-level evaluation
│   └── app/
│       ├── detector.py           real-time pipeline (YOLO, ByteTrack, X3D, smoothing, alerts)
│       ├── infer.py              video / webcam / RTSP front end
│       ├── eval_videos.py        end-to-end evaluation on full videos vs ground truth
│       ├── tune_thresholds.py    alert-threshold sweep from saved logs
│       └── calibrate_boxes.py    fit app.box_map for a camera
├── scripts/                      upload_to_instance.sh (your machine), setup_instance.sh (GPU machine)
├── data/raw/DOAN1/               original dataset (CVAT exports + task backups with the videos)
├── weights/x3d_l_v2_best.pt      trained model
└── outputs/reference/            logs and results of the shipped model
    ├── data/prepare_labels_v2.log label counts per split
    ├── x3d_l/train/              train.log, history.json, final_val_multiview.json, args.json, TensorBoard
    ├── x3d_l/app_eval/           eval.log, summary.json, threshold sweep, per-window logs S07 / S08
    └── x3d_l/demo/               annotated S07 / S08 excerpts (150 s)
```
`data/videos/` and `data/processed/` are generated by `prepare`.

## Run on a new GPU instance (e.g. Vast.ai, "PyTorch (Vast)" template)

```bash
# 1. on your machine (Git Bash on Windows): send code + weights, not the 5 GB dataset
bash scripts/upload_to_instance.sh <ssh_port> root@<ip> /workspace
# 2. on the instance: install, download DOAN1 from Google Drive (~3.7 GB, ~3 min), cut the clips (~6 min)
cd /workspace/cheating_detection_v2 && bash scripts/setup_instance.sh
# 3. use it
python -m cheating_v2 evaluate
```
- GPU memory: training X3D-L with `batch_size: 12` needs ~17 GB (RTX 3090 / 4090 / A5000 or larger). On a 12 GB card
  use `--set train.batch_size=6`. Inference and evaluation fit in ~4 GB.
- `train.workers: auto` uses the container CPU quota (Vast limits CPUs even when `nproc` shows the host count).
- On Vast `/workspace` is usually **not** a persistent volume: copy `outputs/` and new `best.pt` files back
  before destroying the instance (`scp -P <port> -r root@<ip>:/workspace/cheating_detection_v2/outputs/runs .`).
- Tested versions are pinned in `requirements-lock.txt`.

## Setup (own machine)

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # match your CUDA
pip install -e .
```

## Commands

```bash
python -m cheating_v2 download                 # DOAN1 from Google Drive into data/raw (only if data/raw is empty)
python -m cheating_v2 prepare                  # data/raw -> data/videos + data/processed/clips_hr (~6 min)
python -m cheating_v2 train                    # outputs/runs/<run>/best.pt (~20 min on an RTX 3090, 15 epochs)
python -m cheating_v2 evaluate                 # clip-level metrics of weights/x3d_l_v2_best.pt
python -m cheating_v2 infer --source exam.mp4 --out annotated.mp4 --events events.csv
python -m cheating_v2 infer --source 0 --show  # webcam; RTSP/HTTP URLs work too
python -m cheating_v2 eval-videos              # full S07 + S08 videos vs ground truth (~10 min)
python -m cheating_v2 tune                     # threshold sweep from the eval-videos logs
python -m cheating_v2 calibrate                # re-fit app.box_map (new camera angle)
```
Any setting can be overridden: `--set train.epochs=20 app.thr_on=0.9 app.det_imgsz=1280`.
To use a newly trained model by default, copy its `best.pt` to `weights/x3d_l_v2_best.pt`.

## Results of the shipped model (val = S07 + S08, never trained on)

| | value |
|---|---|
| clip level, 3-view (450 clips) | cheat AUROC 0.949, recall 0.848, precision 0.912, macro-F1 0.880 |
| full videos (24 min) | window AUROC 0.911 |
| alerts at thr 0.85 / 0.70, smooth 3, min 2 windows | 42 of 52 cheating events caught (81 %), 22.5 false alarms per person-hour |
| alerts at thr 0.90 / 0.75, smooth 3, min 1 window | 38 of 52 (73 %), 14.7 false alarms per person-hour |

Same accuracy as the 4-class v1 on clips, but about 45 % more false alarms on full videos at the same recall;
raise `app.thr_on` / `app.thr_off` if false alarms matter more than recall. The epoch and the thresholds were chosen
on S07 + S08, so these numbers are optimistic. On a different classroom the model needs labelled data from that
camera. Throughput: ~40 fps on 1080p with 6 people (RTX 3090).
